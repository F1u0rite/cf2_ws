# Ring Flight 项目需求文档 (PRD)

## 1. 项目概述

### 1.1 项目背景
本项目是一个课程比赛项目，目标是实现 Crazyflie 无人机的自主穿环飞行能力。无人机需要根据预先标定（或动态检测）的环位置，自主规划飞行路径，并安全地从一个环穿越到另一个环。

### 1.2 项目目标
- 实现 Crazyflie 无人机的自主起飞和降落
- 实现环位置的标定或检测
- 实现从当前位置到目标环的路径规划
- 实现平滑的轨迹跟踪和穿环动作
- 确保飞行安全和稳定性

### 1.3 技术栈
- **硬件**: Crazyflie 2.1 无人机 + Crazyradio PA
- **定位系统**: Lighthouse V2（推荐，精度高且易部署）/ Loco Positioning / Motion Capture
- **软件框架**: ROS 2 Humble
- **控制库**: Crazyswarm2（`crazyflie_py` Python API）
- **编程语言**: Python 3.10+
- **固件**: Crazyflie Firmware（内置 Mellinger 控制器 + 扩展卡尔曼滤波器）
- **仿真**: Crazyswarm2 内置仿真后端（`backend='sim'`）

### 1.4 开发模式
项目支持两种运行模式：
- **仿真模式**: 使用 `backend='sim'`，无需实际硬件即可测试代码逻辑和路径规划
- **实机模式**: 使用 `backend='cpp'`，连接真实 Crazyflie 飞行

建议开发流程：仿真验证 → 低速实机测试 → 正常速度实机测试

## 2. 功能需求

### 2.1 核心功能

#### F1: 系统初始化
- **优先级**: P0 (必须)
- **描述**: 初始化 Crazyswarm2，连接 Crazyflie，配置 `crazyflies.yaml` 参数
- **验收标准**: 
  - 成功通过 Crazyradio PA 连接到 Crazyflie
  - 定位系统正常工作（位置数据稳定）
  - 固件参数（估计器、控制器）加载正确

#### F2: 起飞和降落
- **优先级**: P0 (必须)
- **描述**: 使用 Crazyswarm2 高级指令实现安全的起飞和降落
- **验收标准**:
  - 起飞平稳，无剧烈抖动
  - 悬停稳定，位置误差 < 10cm
  - 降落平稳，无硬着陆

#### F3: 环位置获取
- **优先级**: P0 (必须)
- **描述**: 获取环的 3D 位置和朝向信息
- **实现方案**:
  - **方案 A（MVP）**: 手动测量并在配置文件中标定环位置
  - **方案 B（进阶）**: 使用外部视觉系统（如 MoCap）实时获取环位置
  - **方案 C（高级）**: 使用 AI Deck 进行机载视觉检测
- **验收标准**:
  - 能够获取至少 2 个环的准确位置
  - 位置误差 < 10cm

#### F4: 路径规划
- **优先级**: P0 (必须)
- **描述**: 规划从当前位置到目标环的飞行路径，包含预接近点和穿越后的安全点
- **要求**:
  - 路径平滑，避免急转弯
  - 考虑环的朝向，从法向量方向接近
  - 预留安全余量（环半径 + 安全边距）
- **验收标准**:
  - 生成的路径可行且安全
  - 路径长度合理

#### F5: 轨迹跟踪
- **优先级**: P0 (必须)
- **描述**: 使用 Crazyswarm2 的 `goTo()` 或 `uploadTrajectory()` 沿规划路径飞行
- **要求**:
  - 使用固件内置的 Mellinger 控制器进行轨迹跟踪
  - 速度可调（0.2-0.8 m/s）
  - 通过 `timeHelper.sleep()` 控制飞行节奏
- **验收标准**:
  - 成功穿过环，不触碰环边缘
  - 轨迹跟踪误差 < 10cm
  - 飞行平稳，无剧烈振荡

#### F6: 多环连续飞行
- **优先级**: P1 (重要)
- **描述**: 连续穿过多个环（至少 2 个）
- **验收标准**:
  - 成功穿过第一个环后，自动飞向第二个环
  - 整个过程无需人工干预

### 2.2 安全功能

#### S1: 紧急停止
- **优先级**: P0 (必须)
- **描述**: 支持紧急停止，立即切断电机或悬停
- **触发条件**:
  - 用户通过 cfclient 或脚本发送紧急停止
  - Crazyswarm2 的 supervisor 检测到异常

#### S2: 边界保护
- **优先级**: P0 (必须)
- **描述**: 在路径规划阶段限制飞行范围
- **验收标准**:
  - 定义飞行边界（建议初始 2m x 2m x 1.5m）
  - 规划的路径点不超出边界

#### S3: 电池监控
- **优先级**: P1 (重要)
- **描述**: 通过 Crazyswarm2 的 status topic 监控电池电压
- **验收标准**:
  - 电压低于 3.8V 时发出警告
  - 电压低于 3.7V 时触发降落（与 crazyflies.yaml 中 voltage_warning/voltage_critical 一致）

### 2.3 监控和调试功能

#### M1: 状态可视化
- **优先级**: P1 (重要)
- **描述**: 使用 RViz2 实时显示无人机状态和飞行轨迹
- **内容**:
  - 当前位置（通过 /cf1/pose topic）
  - 规划路径和实际轨迹
  - 环的位置标记

#### M2: 日志记录
- **优先级**: P1 (重要)
- **描述**: 利用 Crazyswarm2 的 firmware_logging 和 ROS 2 bag 记录飞行数据
- **内容**:
  - 位置、速度、姿态时间序列
  - 电池电压
  - 事件日志（起飞、穿环、降落等）

## 3. 非功能需求

### 3.1 性能要求
- **固件控制频率**: 500 Hz（固件内部，无需用户干预）
- **高级指令频率**: Crazyswarm2 High Level Commander 内部 100 Hz
- **路径规划时间**: < 1 秒
- **定位更新频率**: ≥ 10 Hz（Crazyswarm2 默认 pose topic 10 Hz）

### 3.2 可靠性要求
- **成功率**: 单次穿环成功率 ≥ 80%
- **稳定性**: 连续飞行 3 分钟不崩溃（Crazyflie 电池续航约 7 分钟）
- **恢复能力**: 轻微碰撞后能继续飞行

### 3.3 可用性要求
- **启动时间**: < 30 秒
- **配置简单**: 通过 crazyflies.yaml 和 rings.yaml 配置
- **易于调试**: 支持仿真模式快速迭代

## 4. 约束条件

### 4.1 硬件约束
- Crazyflie 2.1 续航约 7 分钟，载重有限
- 需要 Crazyradio PA 进行通信
- 需要外部定位系统（Lighthouse V2 推荐）
- 飞行空间限制（建议 ≥ 2m x 2m x 1.5m）

### 4.2 软件约束
- ROS 2 Humble
- Crazyswarm2 框架
- Python 3.10+
- Ubuntu 22.04

### 4.3 时间约束
- 项目开发周期（根据课程安排）
- 比赛截止日期

## 6. 风险评估

| 风险 | 影响 | 概率 | 缓解措施 |
|------|------|------|----------|
| 定位系统不稳定 | 高 | 中 | 使用 Lighthouse V2，确保基站安装稳固 |
| 穿环精度不足 | 高 | 中 | 增大环尺寸，降低飞行速度，增加预接近距离 |
| 电池续航不足 | 中 | 高 | 准备多块电池，优化飞行路径减少不必要移动 |
| 碰撞导致损坏 | 中 | 中 | 使用保护罩，先在仿真中充分测试 |
| 开发时间不足 | 高 | 中 | 先实现 MVP（手动标定 + 单环），再迭代优化 |

## 7. 成功标准

### 最小可行产品 (MVP)
- 能够起飞到指定高度
- 能够飞向预设的环位置并穿过至少 1 个环
- 能够安全降落

### 完整产品
- 能够连续穿过 2 个或更多环
- 穿环成功率 ≥ 80%
- 飞行平稳，无明显抖动
- 具备基本的安全保护功能

### 优秀产品
- 能够自动检测环的位置（无需手动标定）
- 穿环成功率 ≥ 95%
- 飞行速度快且平稳
- 完善的可视化和监控界面
